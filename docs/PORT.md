### The additive rule for `lib/skee/types.march`

You may append a type or a constructor. You may not rename, reorder or remove
anything. Re-read the file immediately before every edit, because other agents
edit it too, and keep your edit small. Run `forge check` right after.

A new constructor makes other pieces' matches non-exhaustive, which is a warning
and fails `make check`. Tell the coordinator when you add one.

### Dependency order

Modules may not depend in a cycle, so Swift's mutual references are split:

```
Consts, U64 <- Maths, Rng <- Types <- Units, HoleMap
  <- Items <- Rooms <- Physics, Scoring <- Reducer <- Bots
```

`Pull.strips` belongs to Rooms, because `room.strips` starts from it and
`Pull.spin` needs `room.strips`. Scoring calls `Skee.Rooms.strips`.

Suites: `foundation`, `rng`, `physics`, `scoring`, `items`, `rooms`, `reducer`, `bots`, `presentation`, `scene`, `app`, `painter`, `hud`, `audio`, `host`.

`make test-<piece>` keeps other suites and the `test/*_test.march` wrappers off
its lib path, so a broken suite elsewhere cannot break it (`make selftest` proves
this). A broken module in `lib/` can: March loads every lib-path module that has
a `derive`, a `test` block, or a type or constructor name shared with a module in
use, even if nothing references it (march#1183). `scripts/check_core.py` rejects
shared type names.
`forge test` compiles every test module together: one broken test anywhere fails
it for everyone, and `forge test <file>` still runs all of them. Use `forge test`
as the final gate, not while working.

A stub prints `HARNESS PENDING`: exit 3 from `make test-<piece>`, listed by name
by `make test` and `make test-js`. Pending is never green.

### Your first test

Red, green, refactor, on both targets. A case is native-green and JS-red often
enough that JS is not optional.

1. In `test/suites/<piece>_suite.march`, add `import Harness` and a case.
2. In `test/mains/<piece>_main.march`, replace `Harness.pending` with
   `Harness.report("<piece>", <Piece>Suite.cases())`.
3. In `test/<piece>_test.march`, add the test block its comment shows.
4. `make test-<piece>` and watch it fail for the reason you expect.

```march
fn cases() : List(Case) do
  [
    case("gutter pays nothing", fn -> expect_int(Skee.Units.chips_int(face(Gutter)), 0, "gutter")),
    case("goldens", fn -> all(List.map(rows("shot"), shot_row)))
  ]
end
```

`Outcome` is `Passed(n)`, `Drifted(n, differing, ulps)` or `Mismatch(text)`.
`all` folds outcomes and fails if nothing was compared. An empty suite, a case
that compared nothing, a panic, and a runner that exits 0 without its summary
line are all red.

## Adding golden cases

Expected values come from running the real Swift. Never type them by hand, and
never edit one to make a test pass. If a test cannot pass, report it as failing.

1. Edit `tools/golden/Sources/golden-<target>/main.swift`. Each file has
   `@testable import SkeeCore`, so internal Swift is reachable.
2. Write rows: `g.line("shot", f64(x), i(n), u64(seed), b(flag))`. The first token
   names the row kind. Tokens may not contain spaces.
3. `make golden-<target>` writes `test/golden/<target>.march`. Commit nothing:
   the coordinator handles that.
4. Read rows in your suite:

```march
fn rows(k : String) : List(List(String)) do
  GoldenIo.of_kind(GoldenIo.rows(Golden.Physics.chunks()), k)
end

fn shot_row(row : List(String)) : Outcome do
  match row do
    [speed, want] -> GoldenIo.expect_float(run(GoldenIo.float_of_bits(speed)), want, "speed " ++ speed)
    _ -> Mismatch("bad shot row")
  end
end
```

| Swift writer | Token | March reader |
|---|---|---|
| `f64(x)` | IEEE bits, 16 hex digits | `GoldenIo.float_of_bits`, `GoldenIo.expect_float`, `GoldenIo.expect_libm_float` |
| `u64(x)` | 16 hex digits | `GoldenIo.u64`, `GoldenIo.expect_u64` |
| `i(x)` | decimal, must be JS-safe | `GoldenIo.int` |
| `b(x)` | `1` or `0` | compare to `"1"` |

### Comparing floats

Use `GoldenIo.expect_float` for anything that does not touch libm. It compares
every bit, so it tells `0.0` from `-0.0`.

Use `GoldenIo.expect_libm_float` only for values computed through sin, cos, atan2
or log. On native it is still exact, because native uses the same Darwin libm as
Swift. On JS it allows `GoldenIo.libm_ulps()` (2) and reports each difference as
drift, printed as an `ok~` line. Never raise that number silently: if a value needs
more, report the measured figure. Do not use it to hide a bug in your own code.

### Measured divergence, Darwin libm against V8

From the `rng` suite on JS, 2000 samples each over the core's argument ranges.
Native differs from Swift in none of them.

| Function | Differ from Swift | Worst |
|---|---|---|
| `sin` | 73 (3.65%) | 1 ulp |
| `cos` | 100 (5.00%) | 1 ulp |
| `log` | 126 (6.30%) | 1 ulp |
| `atan2` | 343 (17.15%) | 1 ulp |
| `sqrt` | 0 | exact |
| `next_gaussian` (log, sqrt, cos) | 107 of 1700 (6.29%) | 2 ulp |

The generator's state never diverges: only the returned Float does, and it is
consumed by bots alone.

Physics calls sin and cos, so shots drift on JS. Measured over the physics
goldens and 22 re-seeded generators:

- Position differs on 10.8% of golden shots, usually by far less than a
  millimetre (worst 6.4e-6 m on a shot that stayed on Swift's path).
- 7 of 440,000 bulk shots (1.6e-5) "parted": took a visibly different path. The
  3 examined kept their hole; the other 4 were not examined, so this does not
  show that holes never flip.
- 3 hard comet shots are pinned in the goldens. On V8 they end up to 0.84 m from
  Swift's path, with duration up to 0.146 s different and extra events.
- Replaying with Swift's recorded sines is bit-exact on both targets, so libm is
  the only cause. `Skee.Physics.ShotTrig` and `simulate_with` are that seam.
- Swift `-c release` merges some sin/cos pairs into `__sincos_stret`, which can
  differ from plain `sin`. That is why native as shipped is not exact either
  (worst 4.7e-8 m, 0 parted).

Accepted: a web shot can rarely play differently from the same shot on iPhone.
Runs replay exactly on one target, not across targets.

### Skee.Synth: Swift's 32-bit Float

The synth is Swift `Float` arithmetic. Every Float operation is done in double
and rounded with `Skee.Synth.f32` (Veltkamp's split for normal values, a
`1.5 * 2^-97` shift for subnormals, infinity from `2^128 - 2^103` up, ties to
even). A double holds any sum or product of two Floats closely enough that one
rounding gives Swift's bits: 6031 golden rows of `Float(x)`, ties, subnormals
and overflow to infinity included, are exact on both targets. Where Swift
chains operations, round after each one.

- Swift's `Float.pi` is pi rounded toward zero (`0x40490FDA`), one ulp below
  the nearest Float. Everything that says `.pi` on a Float needs this.
- `sinf` and `expf` are double libm rounded to Float. Darwin's `sinf` differs
  from that on 31 of 3000 phase arguments and `expf` on 16 of 3000, by 1 Float
  ulp. `powf` was exact on the 74 golden rows. Native and V8 give the same
  rounded result on every golden row.
- Over the synth goldens (every cue, combinations, voice stealing, rumble into
  subnormals, drum roll; 57 scripted scenarios) 1457 of 96450 kept samples
  differ from Swift, worst |error| 5.96e-8 (2^-24: one Float ulp for a sample
  in [0.5, 1), more ulps for a quieter one, up to 128). A Swift replica with
  double libm rounded to Float is bit-identical to March for `frameDone` over
  20000 samples, so libm is the only cause. A single sample may be off by up
  to 2^-22, but the case "drift from Swift is pinned" holds the total to what
  was measured: all 96450 compared, at most 1457 off (a +0/-0 difference
  counts), none past 2^-24. Without that pin, going back to double arithmetic
  in the mix, unrounded `sinf`, or dropping `plus_zero` all passed; with it
  each is red. Lower the ceiling when parity improves; never raise it without
  finding the cause.
- That 2^-24 is the worst on the golden inputs, not a bound for the synth.
  Other cues drift by other amounts, always inside the 2^-22 tolerance: a
  verifier measured 2^-23 (1280 ulps on a quiet sample) on its own
  `tallyChips(200)`, `tallyMult(80)`, `combo(40)` scenarios. Playing each of
  those alone on a fresh synth for 176400 samples gives worst 2^-26, 2^-26 and
  2^-25, the same on native and JS (`tools/synth_probe/life`: `synth-drift` is
  the Swift side, `march/drift_main.march` the March side, compared by script).
- Swift drops a voice when `t > decay * 6`, strictly. No game decay ever puts t
  exactly on decay * 6 (checked for every decay in Synth.swift), so the
  goldens cannot tell `>` from `>=`. The case "a voice lives through t ==
  decay * 6" uses a decay (`0x3c20fe0e`) that does, with voice counts and
  samples from the real Swift Synth (`tools/synth_probe/life`, `synth-life`).
  `Skee.Synth.voice` is public for it, as Swift's `v` is.
- `test/golden/synth.march` is 3.3 MB (110891 rows: 96450 `s` samples, 6031
  `fround`, 3000 `sinf`, 3000 `expf`, 2164 `op`, 74 `powf`, 57 each of `len`,
  `sumsq` and `peak`, 1 `floatpi`).
- The LCG is exact Int arithmetic: `seed * 1664525 + 1013904223` stays below 2^53.
- `make test-synth` takes about a minute: the native runner (`--opt 0`) runs for
  46 s, node for 4 s.
- Speed, `tools/synth_bench/run.sh` (M-series Mac, node 26), per `render(128)`
  call (budget 2902 us): idle 19 us, 9 voices 116 us, 48 voices 196 us on node
  (7% of real time); native 27, 251, 292 us. `render(44100)` with 48 voices:
  115 ms on node, 221 ms native.

### Skee.Scene: SceneKit as Canvas 2D

The browser has no SceneKit, so the alley is a pure pipeline and the shell only
paints. Per frame:

```
Skee.SceneCue.frame_cue(k, presentation, held)        what ScenePresenter reads
Skee.Scene.present(world, palette, rig, viewport, keep, cue, dt)
  -> (Scenery, Keep)                                  ScenePresenter.update
Skee.Scene.draw(k, scenery) -> List(DrawOp)           back to front, pixels
```

`rig` is `Skee.Camera.fit_world(k, world)`, worked out once: `Cabinet.fit` only
scores screen heights, so the rig is the same for every viewport and room (all
four rooms share the lane and board height). Keep `Keep` between frames. The
HUD's hole positions are `Skee.Scene.hole_on_screen` (the fitted rig, as
GameModel does), the stroke's geometry `Skee.Scene.flick_geometry`, the aiming
guide `Skee.Camera.guide`, the held ball `Skee.Camera.waiting_ball` and a board
tap `Skee.Camera.tapped_hole`.

`DrawOp` is `ClearTo`, `FillShape(shape, paint, blend)`, `StrokeShape(shape, pen,
blend)`, `DrawText` (centred, in the coordinates of its `frame`, an affine map
for foreshortened badges), `PushClip(shape)` / `PopClip` (save, clip, restore).
Shapes: `Poly`, `Holed` (even-odd), `Polys` (non-zero union), `Disc`, `Outline`
(path steps). `Blend` is `Over` or `Lighter` (`globalCompositeOperation =
"lighter"`). A `RadialPaint`'s centres and radii are in its `frame`: build the
path in pixels, then set the frame before `fill`. Colours go to CSS through
`Skee.Scene.css`, sizes in fonts through `css_number`: `float_to_string(1.0)` is
`"1."`, which CSS rejects. `tools/scene_preview/paint.html` is a complete
reference painter in 60 lines of JS.

Parity, all against the real SkeeScene (32-bit Float there, 64-bit here):

- World mappings, `Cabinet.fit` for seven viewports (390x844 to 1920x1080),
  projected lane corners, hump, crease, every hole and ball centre: worst
  1.6e-7 m and 5.6e-5 px. Tolerances 1e-6 m and 1e-3 px; a lane point is a
  32-bit ray cast, measured 1.43e-6 m, allowed 2e-6.
- The cabinet's node tree for every room (108 nodes: kind, size, colour,
  outline, visibility, opacity, world transform) matches part for part.
  `Cabinet.setReel` coins and halos, and `lightBulbs`, match.
- `ScenePresenter.update` replayed over 984 frames of three real throws (replay
  "a") and 311 frames of a marshmallow throw (replay "e"): ball, shadow, trough
  count and camera position match to 1e-6; the roll quaternion, checked one
  frame at a time, to 1e-4 (measured 1.8e-5). The ball's scale is read off the
  `BallPart` the model draws (place scale, `drawnSize`, the 0.35 bounce
  swell), so replay "e" checks the marshmallow's drawn size. On the 63 frames
  (both replays) where the ball sinks straight into a hole
  (`Skee.Scene.rolls_straight_down`) Swift's roll axis is a normalised cross
  product of rounding noise, so the ball spins at random; the port does not
  roll it there, and those frames' orientation is not compared. Gutter sinks roll in both and are compared.
- Replay "b", 3168 frames of a whole nine-ball frame (seed 7, with pulls),
  feeds what replay "a" leaves fixed: `excited`, the symbols shown so far, the
  top slot and the reels' positions. Per frame it compares each reel's shown
  symbol, halo opacity and colour, first coin's swell, hiding and emission,
  every bulb, every ring of light's scale and opacity, and the camera's
  position (1e-6) and look direction (2e-6). The runner prints how many frames
  reached each path (glow 1: 82, glow 2: 257, hole flash: 50, slot halo: 330,
  excited: 570, leaning: 2743, rings: 416), and the case fails if any is 0.
  Mutating the glow, flash age, chase rate, ring life or look lean turns it red.
- Replays "c" (620 frames, three comet throws) and "d" (900 frames, three
  jumping-bean throws) are recorded the same way, for the rings of light that
  "b" never sends: a comet's at the hump (0.9), back wall and rails (0.4), a
  bean's on every hop (0.25), and none when a bean hits a wall or rail. Each
  fails if it never reaches its path (c: comet hump 3, back wall 3, rail 2
  frames; d: hops 13, plain wall or rail 2). Mutating any of those sizes, or
  giving a non-comet a wall ring, turns it red.
- `Textures.lane`, `.ball(kind)` for all five balls and `.wave`, pixel for
  pixel: rows of the real images (every 8th lane row, every 2nd ball row, every
  4th wave row) against `Skee.Scene.texel` over the marks the draw paints
  (`lane_marks`, `ball_marks`, `wave_marks`). Only pixels wholly inside or a
  half-diagonal clear of every visible mark edge are compared (122425 lane,
  about 60800 per ball, 15388 wave); worst 1.8 8-bit steps on the lane, 0 on
  the wave, tolerance 2. Every drawn mark must be on top in some compared
  pixel. A 16-step change to a seam, grain, arrow, stripe or ring colour, the
  grain's alpha, the arrow's ink width or height, the gold ring's width or the
  caps' rows turns it red; a 1-step change is inside CoreGraphics' rounding.
  The lane slab's side colour is the node tree's. What is not pixel-checked:
  how `paint_mark` and the ball's latitude bands put those marks on screen.
- `Textures.lane`'s nine board tones, read off the real texture (each board's
  commonest 8-bit pixel), match `Skee.Scene.lane_plank_tones` within one step.
- `Cabinet.fit`'s grids are Swift Float strides, whose lengths differ from a
  Double's (`-1.8 through -0.2 by 0.05` stops at -0.25): the counts are Swift's.

Deviations, where Canvas 2D has no equivalent:

- No depth buffer: parts are painted in a fixed order by role (`Skee.Scene.layer`),
  the ball last. A sinking ball is clipped to its pit and what is above it.
- Toon lighting is worked out per flat face (per patch on balls), in linear
  light: the cel ramp's three bands, the hemisphere fill and the rim band. The
  floor's per-pixel rim is drawn as four rings. No cast shadows; the ball's
  blob shadow is drawn.
- Outlines are silhouettes stroked under the fill at the inverted hull's screen
  width (`thick * height / (40 tan(fov/2))`), not hulls. Boxes are not chamfered.
- Spheres are circles; the ball's gores are 30 lit patches. Gore seams are not
  drawn (`Undrawn` in `ball_marks`; `texel` leaves their pixels out).
- Not drawn yet: particles (trail, sprays, drop bursts, Hot Spot glitter).
  Fonts fall back from Avenir Next Heavy to Nunito or sans-serif.

Speed (`tools/scene_preview/bench.sh`, node 26, an idle machine): `Cabinet.fit`
20 ms once; `present` plus `draw` 0.51 ms a frame over the 1295 golden frames
of replays "a" and "e", at most 532 ops (budget 16 ms, 2000 ops). Under load from parallel builds a
verifier measured 44 ms and 0.85 ms: still far inside the budget.
`test/golden/scene.march` is not in `make golden`: regenerate it with
`make golden-scene`. `tools/scene_preview/preview.sh <stage> <w> <h>
<dir>` paints a frame in headless Chrome; `tools/golden_scene`'s
`scene-snapshot <png> <w> <h>` renders the real SceneKit cabinet beside it.

### Skee.App: GameModel as a pure model

The shell holds one `Skee.App.Model` and does three things with it:

```
Skee.App.boot(k, saved, width, height, seed) -> (Model, List(Effect))   once
Skee.App.update(model, msg) -> (Model, List(Effect))                   every event
Skee.App.scene_ops(model), Skee.App.hud(model)                         every frame
```

`Msg` is `MsgTick(now)`, `MsgPointerDown/Move/Up` (FlickSamples: seconds,
CSS pixels), `MsgPointerCancel`, `MsgTap(Intent)`, `MsgResize`, `MsgVisible`
and `MsgAutoplay` (LaunchArguments' `-autoplay`). Every HUD button is an
`Intent` constructor; `Skee.App.accepts` says whether it is on screen and on
top, so a tap under an overlay does nothing, as in SwiftUI. `Effect` is
`FxSound(Skee.Synth.Sound)`, `FxRumble`, `FxDrum`, `FxSave(SaveKey, text)` and
`FxHaptic`. The shell owns the storage key for each `SaveKey` and hands the
stored strings back at boot as `SavedStrings`. Rumble and drum effects are
sent only when the level changes; Swift sets them every frame to the same value.

Times: one clock for everything, `performance.now() / 1000`, which is what
requestAnimationFrame passes and what every pointer event's `timeStamp` is
measured on. The tick clamps its step to 1/20 s as `Stage.advance` does.

Deviations from GameModel:

- One tick does what SceneKit's render thread and the display link did
  separately: advance the presentation, then haptics, sounds, rumble, drum,
  the scene's `present`, and autoplay.
- New games are seeded from a SplitMix64 stream started from the boot seed,
  not from `Date()` seconds. The shell passes the launch's seed.
- The host is a placeholder (`HostTable`, `HudState.HostPlaceholder`) with one
  button, close. Swift's open haggle only closes, which would leave a player
  whose host is due unable to start a game, so closing behaves as a table left
  without a deal: after Sal's lines it marks the arrival done (Swift's `settle`
  does that) and starts the walkthrough; after NEW GAME it starts the game;
  opened from a button it just closes. `games_since_host` is not reset, so the
  placeholder sits down again before every new game until the host is ported.
  Sal's five arrival lines are ported (`arrival_beats`).
- `MsgVisible` has no Swift counterpart (iOS pauses the display link): hidden
  stops the stroke, the rumble, the buzz and the drum, and restarts the clock.
- No hinge: `fold` is 0. No safe-area insets.
- Haptics are effects; the browser may vibrate or ignore them.

`make test-app` (about 22 s native, 7 s on node) drives `update` with Msg
sequences: the first launch through Sal, the placeholder and the walkthrough
(skipped, and played to its end), strokes and fouls, the lever, the counter,
the shop, rooms, the host's seat, tips, and a run from the title to ante 2
throwing the bot's aim book's best launches, whose saved strings boot back
into the same run. Ten hand mutations of `app.march` (saving the practice
run, the trail's life, the overlay gate, the board tap, counting abandoned
games, the host's close, a cue's sound, the rumble, the tip save, the bet
gate) each turn the suite red.

### Skee.Painter and the shell

Per frame the shell does `update(m, MsgTick(t))`, then
`Paint.frame(ctx, k, dpr, w, h, Skee.App.scene_ops(m))`, then
`Hud.render(hud, m)`, whose queued taps it dispatches as `MsgTap`.
`Skee.Painter.calls(k, dpr, w, h, ops)` turns DrawOps into a list of
`CanvasCall`s in paint.html's order: the frame opens with `setTransform(dpr,
0, 0, dpr, 0, 0)`, a radial paint or a lettering composes its `frame` onto
that inside save/restore, Holed fills and clips even-odd, a disc's negative
radius is 0, a stray PopClip restores nothing and open clips are closed at the
end. `shell/paint.march` executes the list with one match and decides nothing.

The shell (`shell/game.march`) keeps one `ShellState` (model, canvas,
context, HUD and audio handles, size, dpr) in a cell in `web/skee_glue.mjs`,
so pointer callbacks, visibility changes and the frame loop act on the same
model, each through `dispatch(msg)`: update, store, perform. Effects:
`FxSave` to localStorage (`skee.wallet`, `skee.run`, `skee.tipsSeen`,
`skee.walkthroughDone`, `skee.arrivalDone`, after Swift's names), `FxHaptic`
to `navigator.vibrate` (impacts and notifications; the rolling buzz has no
browser equivalent), and every effect to `Audio.apply`. Pointer input follows
one pointer at a time (ThrowPad's `isMultipleTouchEnabled = false`), with
pointer capture and coalesced samples (`coalescedTouches`), timed by
`event.timeStamp / 1000`, the rAF clock. The window size and
devicePixelRatio are polled each frame; a change resizes the backing store
and sends `MsgResize`. The launch seed is two `crypto.getRandomValues` limbs.

Entry points other shell pieces fill in: `Hud.mount(root : Js.Dom.Node) :
HudHandle`, `Hud.render(h : HudHandle, m : Skee.App.Model) :
List(Skee.App.Msg)`; `Audio.start() : AudioHandle`, `Audio.apply(a :
AudioHandle, effects : List(Skee.App.Effect)) : ()`. The stub HUD shows one
button per argument-free Intent that `Skee.App.accepts`. `Glue.queue_tap(i)`
and `Glue.drain_taps()` are a tap queue for HUD buttons. `<html>` carries
`data-layer`, `data-can-throw`, `data-busy` and `data-crease-y` for the
playtest.

FFI added (`web/skee_glue.mjs`, declared in `shell/glue.march`): the clock
and rAF in seconds, view size, devicePixelRatio, canvas sizing, seed limbs,
visibility, vibrate, pointer capture and coalesced samples, the state cell,
the tap queue, data-* marks, and the Canvas calls Js.Canvas lacks
(setTransform, globalCompositeOperation, fill and clip with a winding rule,
lineCap, lineJoin, text centring, a full arc, radial gradients).

### Skee.HudView: SkeeHUD as HTML

The HUD is DOM over the canvas. `Skee.HudView` is pure; `shell/hud.march`
only writes its text into elements and queues clicks:

```
Skee.HudView.defs(k) -> Html                     once: <symbol>s for the art
Skee.HudView.view(k, Skee.App.hud(m), local, w, h)
  -> List(Section)                               every frame, fixed ids, back to front
Skee.HudView.decode(code) -> Option(HudAction)   a click's data-act
Skee.HudView.react(local, hud, action)           -> (HudLocal, Option(Intent))
Skee.HudView.settle(local, hud)                  the Guide forgets its page when closed
```

- HTML is data (`Html = Tag(name, props, kids) | Words(text)`); `render`
  escapes every text and attribute value (`& < > " '`).
- Every tappable element carries `data-act`, an Int code for its
  `HudAction` (`ActIntent(Intent)` or a Guide page turn), and `data-intent`,
  its name, for people and the playtest. The shell delegates one click
  listener on `#hud`, walks up to the nearest `data-act`, and queues the code
  with `Glue.queue_tap`; `render` decodes the queue, so the shell never
  interprets a tap. Skee.App still gates every Intent with `accepts`.
- Panes under the top `Layer` are drawn `inert` (no `data-act`), as SwiftUI's
  overlay takes every touch over what is under it. The suite checks, over
  eleven model states, that every button drawn is one `Skee.App.accepts`, and
  that the title under Sal or the shop is not tappable.
- GuideView's `@State` (topic, page) is `HudLocal`, kept by the shell as text in
  `#hud`'s `data-local` (`save_local`, `load_local`), with the lever's drag
  (Lever's `@State drag`). Nothing else is view state: bets, offers and
  charms are all model Intents.
- A pane is rewritten only when its HTML changed (the last text is in the
  pane's `data-src`): an idle frame mutates nothing (the playtest measures 0
  mutations a second on the title), and a press on a button is not lost to a
  rewrite of another pane. Animated things (popups, tally, banner, coin rain,
  the hot spot, the aiming dashes, the reels while spinning) are in panes
  with no buttons except the machine, whose SPIN is disabled while it spins.
- Art: the slot symbols are `Skee.Scene.symbol_ops` (Textures.drawSymbol in
  its 256 texture's inner 216) turned into SVG by `ops_svg` (clips as
  `<clipPath>`s); PrizeArt.drawPrize is ported to SVG directly (`prize_art`),
  lit and as a silhouette, 56 `<symbol>`s mounted once and referenced by
  `<use>`. CelText is CSS `text-shadow` (eight ink copies at `max(1.5, size *
  0.08)`, dropped 0.6 of that), Pill a 3px ink border inside and a 4px ink
  `box-shadow`; StripeBackdrop a repeating gradient. Fonts: `ui-rounded`
  (SF Pro Rounded on Apple), else Nunito 900, the nearest web font.

Deviations from SkeeHUD:

- (Was: the lever is tapped, not dragged. Fixed after playtest round 1.) The
  knob is a drag handle as in Swift's Lever: `Skee.HudView.lever_touch` takes
  its pointer (`LeverDown/Move/Up/Lost`, from `Glue.on_drag`, captured on the
  HUD root because the knob is rewritten as it moves); past 2pt it follows the
  thumb, clamped to its 156pt travel; let go past half way it sends
  `TapPull`; a tap does nothing; it springs home with SwiftUI's
  `.spring(response: 0.25, dampingFraction: 0.45)` on the HUD clock, kept in
  `HudLocal.lever` (saved in `data-local`). A second grab during the spring
  starts from the top, not from where the spring has got to.
- No safe-area insets: `topInset` is 0, so the top bar sits 8px down and
  "TARGETS · hit one = combo" always shows when there is no combo, as in
  Swift with no island.
- The host is a labelled placeholder (THE HOST, PLACEHOLDER, CLOSE), the
  `HostSeam` seam; the title's room picker and "THE HOST WANTS A WORD" buttons
  are real (`TapOpenHost`), as is GameOverView's.
- SwiftUI's springs and `.transition(.opacity)` on Sal's lines are not
  animated; popups, the banner, the tally, coins and the hot spot follow the
  same per-frame formulas as Swift.
- Text that SwiftUI shrinks to fit (`minimumScaleFactor`) is clipped or wraps.

### Audio: Skee.Synth in real time

The synth runs in an AudioWorklet, one 128-sample block per render quantum,
not as pre-rendered per-cue buffers: the synth's state is shared (one noise
LCG threaded through the rumble and every noise voice, voice stealing at 48,
the rumble low-pass and drum clock always running, the clip on the mix), so
only one live synth sounds like Swift's.

```
update -> effects -> Skee.SoundOut.commands -> List(AudioCmd)     main thread
  -> port.postMessage (a structured clone of March's plain-object values)
  -> each quantum: Skee.SynthFeed.block(synth, cmds since last, 128)   worklet
  -> Float32 mono -> gain 0.8 (mainMixerNode.outputVolume) -> speakers
```

- `make web` builds a second entry, `shell/synth_worklet.march`, into
  `dist/skee_synth_worklet.mjs` (340 KB: Skee.Synth and Skee.SynthFeed, no
  game), which `audioWorklet.addModule` loads. It imports
  `march_runtime.mjs` in the worklet's realm; nothing in the runtime touches
  `window` or `document` at load. Each processor starts from a silent synth
  (`SynthEngine.reset`): one module-level cell serves every processor in a
  realm, so the constructor resets it.
- The AudioContext is made on the first gesture (pointerdown, pointerup,
  touchend, keydown, click, captured on window), at 44100 Hz with
  `latencyHint: "interactive"`, and resumed on later gestures while not
  running. Hidden page: suspended; shown: resumed. Before the speakers are
  up a cue is dropped (it would play late) and the rumble and drum levels are
  tracked (`Skee.SynthFeed.track`), then restored (`restore`) the moment the
  synth comes up. A browser that ignores `sampleRate` gets linear
  resampling in the pump (`web/skee_synth_cell.mjs`).
- No AudioWorklet (an insecure context such as a phone on plain http over
  the LAN, an old browser) or a failed `addModule`: a ScriptProcessorNode of
  2048 samples runs `SynthEngine.serve` on the main thread, between frames.
  No AudioContext at all: silent, nothing thrown.
- A command lands on the first sample of the block after it arrives, as
  Swift's lock does at the next render callback. Measured in headless
  Chrome, every batch reached the synth in the next quantum or the one
  after (worst 5.8 ms after the send); `playbackStats` reported 0 underruns.
- Parity (`make audio-check`): the shipped worklet in an
  OfflineAudioContext at 44100 Hz, on the 48 golden scenarios that are one
  cue then silence (78188 kept samples), against the real Swift Synth:
  1264 not bit-identical, worst |error| 5.96e-8 (2^-24), tolerance 2^-22.
  The same bundle under node with a stand-in worklet scope
  (`tools/audio_check/worklet_node.mjs`) gives the same 1264 and the same
  worst: Chrome's V8 and node's agree, and the drift is libm's (see
  "Skee.Synth" above).
- `<html data-audio>` is the context's state (`none` before a gesture),
  `data-audio-path` is `worklet`, `script` or `off`, and
  `window.__skeeAudio.log` keeps the last 400 batches sent (page time, audio
  time, the commands, and the audio frame at which the worklet took them).

### Skee.Host: the casino host, with no scripted host

A language model plays the host through the same-origin relay
(`/skee-host/chat`, relay/relay.mjs). The core never touches the network: it
says what to send and takes what came back.

```
Skee.Host.new_haggle(k, room, seed, visit) -> Haggle              Haggle.init
Skee.Host.seat(haggle, consent) -> (HostSession, Option(HostCall)) GameModel.seat (+ askGreeting)
Skee.Host.answer_consent(s, yes), reconsider(s)                    the AI chat card
Skee.Host.player_says(s, text) -> (HostSession, Option(HostCall))  hostSay + askHost
Skee.Host.deliver(s, call_id, status, body) -> (HostSession, Option(HostCall))
Skee.Host.call_failed(s, call_id, reason) -> (HostSession, Option(HostCall))
Skee.Host.retry(s), sign(s)                                        after a failure (a reply's or the hello's); DEAL
Skee.Host.request_body(call) -> String                             the JSON to POST
```

- A `HostCall` is one POST: `call_messages` (system prompt first, then the
  transcript, exactly `Haggle.messages` or `greetingMessages`), `call_id`
  to hand back, and which of DeepSeek.guarded's three tries it is. The shell
  POSTs `request_body(call)` and passes the HTTP status and body to
  `deliver`, or a network error to `call_failed`. An answer to a call the
  session is no longer waiting for is ignored.
- `request_body` writes every code point below U+0020 as `\u00XX`, as
  JSONSerialization does. stdlib `Json.to_string` writes all but `\b \t \n
  \f \r` raw, which Node's JSON.parse in relay.mjs refuses (400 "not a
  haggle"), so one such character in a reply's `say` or a player's line
  (U+000B comes with text pasted from Word) would have broken every later
  call of the haggle (`tools/repros/json_to_string_controls.march`; wire
  rows 68 to 71, and the suite's check that no body holds a raw byte below
  0x20).
- `deliver` reads the response as DeepSeek.chat does (not 200: `FailHttp`;
  a body JSONSerialization refuses: `FailMalformed`, including a raw control
  character, a bad escape, a lone surrogate or a bad or infinite number in a
  field nothing reads, which JSONDecoder would only scan (`serialization_reads`;
  trailing commas, a BOM and `1e-400` it reads, wire rows 35 to 67);
  no `choices[0].message.content` text: `FailMalformed`; `finish_reason:
  "length"`: `FailTruncated`), parses the content as DeepSeek.parse does
  (`parse_reply`: trim, ``` fence, JSONDecoder's rules through
  `Skee.Save.parse`, empty `say` refused), and checks it with
  `Haggle.accepts` (a greeting with `HostGuard.allows`). A refused reply
  returns the next call: the same messages plus DeepSeek's system note, at
  most three tries, then `FailUnreadable`. Accepted: `hear` (or `greet`).
- View state (`HostState`): `is_waiting` (thinking), `shown_lines` (the stock
  hello hidden while the model writes one), `thinking_text`, `takes_lines`,
  `can_sign`, `can_retry`, `failure`, `greeting_failure`, `subtitle`,
  `terms_note`, `ending_title`, `ending_terms`, `close_label`, `nudges`;
  `describe_failure` is DeepSeek.Failure's console text. While the hello is
  being written `takes_lines` and `can_sign` are false: HostView disables
  SAY, the nudges and DEAL on `host.thinking`, which GameModel sets to
  `hostThinking || hostGreeting`, though `hostSay` and `hostDeal` themselves
  check only `hostThinking`. The AI chat card's texts are the HUD's.
- `Skee.Save.parse` marks text Swift's decoder refuses with in-band strings
  (U+0007 "skee-unreadable" U+0007, and "skee-underflow"). A string or key
  that really starts with U+0007 gets one more U+0007 in front, and
  `Skee.Save.text_of` takes it off, so no input can spell a mark (parse rows:
  a `say`, an ignored key and a `mood` spelled as a mark read as Swift reads
  them).

Deviations, deliberate (the user's direction): no scripted fallback host.

- `ScriptedHost` is not ported. When a call fails (network, any HTTP error
  including 429, truncated, malformed, or three unusable replies) the session
  records `WaitFailed(HostFailure)`: no host line is invented, the offer and
  patience do not move, and the player may `retry` (the same request, from
  try one), `sign` the offer on the table, or leave. No new line is taken
  while the failure shows.
- After `HostGuard.maxModelTurns` (25) player lines, where Swift's scripted
  host would answer, `takes_lines` is false: sign or leave.
- With consent refused or not given, nothing is sent and no line is taken
  (Swift's scripted host answered those players).
- A line `HostGuard.screen` flags is answered at once by the guard's own fixed
  reply (`deflection`: the 988 line, personal details, real money, and the
  host's off-topic wave-offs from the Phrasebook) and never sent to the model:
  `deflects(concern)` is true for every concern. The task names crisis,
  personal details, real money and the off-topic/adult wave-offs; trickery
  is not named. Deflecting it is the port author's reading, because Swift's
  `deflection` answers `.offTopic, .trickery` in one arm with the same
  Phrasebook wave-off; it is a decision for the user (`deflects` is one
  line). It reaches beyond Swift's live path, since the phrases are matched
  as substrings: "in fact as a friend, more tickets?" holds "act as" and is
  waved off without the model being asked, as a money phrase inside a longer
  word is. In Swift's live path only
  personal details and crisis were kept off the wire (as stand-in notes) and
  the rest went to the model. The deflection is heard through `hear`, so an
  adult line at the last of a host's patience still walks them out, as with
  Swift's scripted host. Later `messages` are Swift's own: crisis and personal
  lines become "(removed)", other screened lines are sent verbatim as history.
- A greeting that cannot be had leaves the stock hello showing (Swift's
  `try?`); it is the haggle's own opening line, not an invented reply. The
  failure is kept, typed, as `greeting_failure` (until the player speaks,
  when there is no hello left to ask for), and `retry` asks for the hello
  again. It blocks nothing: the player may talk or sign meanwhile.
- Safety consequence of the above: while `takes_lines` is false (consent
  refused or not given, 25 lines said, a failure showing, a call out) no line
  is screened, so the 988 deflection cannot be reached in those states, where
  Swift's scripted host would have answered a crisis line. The input is
  disabled there, so nothing typed goes unanswered.

Findings, kept as Swift has them:

- DeepSeek.guarded's retry note is a second `system` message, which
  relay.mjs refuses (`messages[i>0]` must be user or assistant): through the
  relay every second try gets HTTP 400, so a refused reply ends in
  `FailHttp(400)`, as Swift's client would then throw. `relay_accepts` ports
  the relay's rules; the case "three refused replies, the retry note, and the
  relay" pins it. Changing the note's role is a decision for the user.
- A number past 2^53-1 in a reply is held at 2^53-1 with its sign (every term
  is clamped and mood is read for its sign, so the rules give Swift's
  result), but `Haggle.json` then writes 9007199254740991 where Swift writes
  the number sent. Whether Swift reads such a number at all is decided from
  the token's text, not its Double (`decoder_numbers`, before
  `Skee.Save.parse`): JSONDecoder reads an integer token exactly in Int64's
  range (so 2^63-1 is read and -2^63-1, which is -2^63 as a Double, is
  refused); any other token through its Double, which must lie in Int64's
  range, and from 2^53 up through a Decimal (mantissa below 2^128, later
  digits dropped, trailing zeros off, below 2^64 if it has a fraction, whole
  part truncated and at most Int64.max, so `-9223372036854775808.0` is
  refused while `-9223372036854775808` is read, and `9007199254740991.5`
  reads as 9007199254740991). Repair round 3; the earlier round's note that
  2^63-512..2^63-1 were refused here is fixed, and it had missed the negative
  side (-2^63-1 down to -2^63-1024, then read here as -(2^53-1)).
- JSONSerialization's number rule, which `serialization_reads` applies to
  every token of the envelope: an exponent written in more than four
  characters is refused (`1e00001`, `1e-1000`; `1e-400` is read); up to 17
  digits (a lone `0` before the point not counted) is a Double, refused only
  at +inf (`-1e400` is read, as -inf); more is a Decimal, refused if its
  exponent leaves -128...127, checked digit by digit and then with the
  written exponent (`1` and 200 zeros, `0.` 200 zeros `1`, even `0.` and 200
  zeros, `9.99999999999999999999e307`). Probed on this machine's Foundation
  (macOS 27.2, Swift 6.4.2) over about 100000 tokens against a model
  (`tools/num_probe/model.py`, `batch.swift`), and pinned by golden rows:
  690 tokens as `serial` envelopes, the same tokens as a reply's mood and as
  offer.nights (with an unread copy) in `parse` rows, and wire rows 68 to 76.
  These are Foundation's rules, which another OS release could change.

Swift's String, as `Skee.SwiftText`: every comparison the guard makes is
Character by Character with canonical equivalence (`"kill myself\u{301}"`
does not contain "kill myself"; "kill\u{A0}myself" does after the split; the
Kelvin sign lowercases to "k"), counts are Characters, and isLetter,
isNumber and isWhitespace read the first scalar. `Skee.UnicodeData` is
generated by `golden-unicode` from this machine's Swift runtime: scalar
properties, the lowercase mapping, CharacterSet.whitespacesAndNewlines, the
three canonical singletons onto ASCII, and Grapheme_Cluster_Break,
Extended_Pictographic and Indic_Conjunct_Break as String's own grouping shows
them (probed scalar by scalar). Each table is a binary decision tree in code,
so a lookup allocates nothing and reads no string on JS (a 4-entry byte-view
cache made a table string thrash). Segmentation is UAX #29's rules (GB3 to
GB13, GB9c included) over those classes.

Parity, against the real SkeeCore and SkeeNet (`make golden-host`, 50788
rows, 5.5 MB; reproducible run to run): 9868 strings' Characters (with each
one's letter, number, whitespace and ASCII key), lowercasing and every
lowercase mapping, 5936 scalars' properties, prefix and count; HostGuard.screen
over 8720 lines (every phrase and word in about forty spellings: case, punctuation,
NBSP, ideographic and line separators, CRLF, combining marks, Kelvin K, dotted
I, fullwidth, zero-width spaces, near misses; digit runs in every script and
separator; emails; 2500 fuzzed lines), with hasPersonalInfo, the words and the

## Rules every core module follows

- `cap pure` at the top, `needs ()` on every `fn` and `pfn`, no `needs` lines.
  The compiler does not catch `Js.*` or `System.*` from a module with no needs
  lines, so `scripts/check_core.py` is the only complete guard.
- Annotate every signature. Match exhaustively, listing constructors: a missing
  constructor is only a warning, which `make check` turns into a failure.
- Same rules, constants, numbers and RNG call order as the Swift. Where Swift's
  `max`, `min` or `clamp` is used, use `Skee.Maths`: argument order decides ties.
- A pure function that draws takes the `Rng` and returns `(value, Rng)`.
- No `panic` in the core. Swift's `precondition` becomes a refinement or a Result.

## March gotchas

Each one was hit on this build. `scripts/check_core.py` enforces the ones marked
(guard). Repros are in `tools/repros/`.

### Silent wrong answers

- **Float literals on JS (guard).** The emitter prints 12 significant digits, so
  a literal with more is truncated. `Math.pi`, `Math.tau` and `Math.e` are hit too.
  Put such constants in `Skee.Consts`.
- **Constant folding on JS.** `opt.fold` turns `1.0 /. 240.0` into a literal, which
  is then truncated. It sees through inlined functions and record fields, so
  `spec.a *. spec.b` can be hit with no long literal in sight, and no grep finds it.
  Every JS build here uses `--disable-pass opt.fold` (`MARCH_DISABLE_PASS=opt.fold`
  for forge). Native tests cannot see this bug. (`fold_truncates.march`)
- **Module-level `let` on JS (guard).** Outside the entry module, even `let i = 7`
  compiles to a closure object: it prints `[object Object]` and adds as a string.
  Write `fn i() : Int do 7 end`. (`lib_let/`)
- **`==` on records, native (guard).** All record types share one `__march_eq_Ptr`,
  built for the first record seen: wrong answers or a segfault. Records in this
  project do not derive Eq, so `==` on one is a compile error, and `run-suite.sh`
  also rejects any native build containing that symbol. Write a named comparison,
  as `Skee.U64.equal` does. (`record_eq/`)
- **`derive Ord` (guard).** Compiles, and `<` type-checks, but `<` is false and
  `compare` is 0 on native and JS. Nothing here derives Ord, so `<` on an ADT is a
  compile error. Use `Skee.Units`' ranks. (`derive_ord.march`)
- **Prefix minus is a call to `negate` (guard).** A function of yours called
  `negate` captures it, and `-1.0` inside it recurses forever. (`negate_shadow.march`)
- **`None` in an `Option(Float)` field, native (guard).** An unannotated `let`
  holding a record with such a `None` segfaults at drop time. Annotate the `let`
  with the record type, as `start_sim` does. (`none_float_field.march`,
  march#1173)
- **`0.0 +. x` is folded to `x`, every target.** Even with `opt.fold` off. When
  `x` is `-0.0` the IEEE answer is `+0.0`, so the sign of a zero is lost. Write
  `if x == 0.0 do 0.0 else x end` where it matters (`Skee.Synth.plus_zero`).
  (`synth/fold_probe.march`)
- **Let-bound lambdas over records, native.** A `let f = fn ... ->` that captures
  a record and puts an Int argument into a record returns its tagged form
  (2n + 1: 15 for 7), and one that takes a record argument and builds a record
  segfaults. JS is right. Use named functions; Skee.Scene and Skee.Camera have
  no let-bound lambdas. (`lambda_tagged_int/`)
- **Int on JS.** Doubles: exact to 2^53-1. The JS runners use `--js-int-check`, which
  throws past that. Anything wider goes through `Skee.U64`.

### Tools

- **`forge format` deletes code (guard).** The body of `match do` becomes the literal
  text `match do ... end`, and a multi-statement lambda inside a list literal
  becomes `fn x -> ...`. Use `make format`, which refuses, and never `match do`:
  chain `if ... else if ... else ... end end` instead. Put multi-line lambdas in a
  named function. (`format_deletes.march.txt`)
- **`forge format` breaks non-ASCII string literals.** It prints each byte past
  127 as a decimal escape (`"\194\183"`), which the lexer rejects, so the
  formatted file no longer parses; `\xc2\xb7` is rewritten the same way. Keep
  literals ASCII and build such characters with `String.from_codepoint`, as
  `Skee.Presentation.middle_dot` and `times_sign` do. (`format_escapes_utf8.march.txt`)
- **`forge format` deletes an `if` branch holding several statements** inside a
  match arm's `do` block: it becomes `if c do ... else x end`. `make format`
  refuses it. Move the branch into a named function. (`format_deletes_if_lets.march.txt`)
- **`forge format` moves a `--` comment out of a function body** (before a
  `let`, or inside a match arm's `do`) to just after the function, where it
  reads as the next function's comment. `make format` does not catch it. Put
  comments above a function, or give the commented piece a function of its own.
  (`format_moves_comments.march.txt`)
- **`forge format` drops the parentheses around an `if` used as an operand**:
  `(if c do a else b end) *. x` becomes `if c do a else b end *. x`, which does
  not parse, and `n + (if ...)` the same. Bind the `if` to a `let` first.
  (`format_drops_parens.march.txt`)
- **`forge format` rewrites `a && f(xs, fn x -> <several lines>)` as
  `&&(a, f(xs, fn x -> ...))`**, which does not parse. Seen in
  `Skee.Host.relay_accepts`. Pass a named function instead of the lambda.
  (`format_and_lambda.march.txt`)
- **`forge format` deletes a `resource` declaration**: `resource Gradient`
  becomes `type Gradient = `, which does not parse. `make format` does not
  catch it. The shell has no resource type; the glue keeps the gradient.
  (`format_deletes_resource.march.txt`)
- **`forge build` puts only `lib/` on the module path**, so it cannot build
  `shell/game.march`, which uses `shell/`'s modules. `make build` and `make
  web` call `march` with `MARCH_LIB_PATH=lib:shell`; `scripts/check.sh` checks
  with `lib:test:shell`.
- **`python3 -m http.server` is unreachable on this machine's loopback**: the
  connection times out, sandbox or not. `make serve` uses `tools/serve/serve.mjs`.
- `forge format` also moves a file's leading comment inside the module, turns
  `use X.*` into `import X`, and rewrites `doc "x"` to `doc """x"""`.
- A parse error in `lib/` shows up in dependants as `Unknown module`. Run
  `forge check` for the real message. A missing function also reads `Unknown module`.
- `forge check` and `forge lint` cover `lib/` only and exit 0 on warnings. Use
  `make check`.
- Native builds leave a `.ll` next to the entry file. `*.ll` is ignored.
- Refinement hints (`refinement_unverified`) are not failures: the checker reports
  only what can never hold. Silence is not proof.

### Language

- Keywords that bite as names: `state`, `init`, `on`, `send`, `loop`, `spawn`,
  `within`, `only`, `alias`, `import`, `requires`, `invariant`, `strategy`,
  `permanent`, `temporary`, `transient`, `offer` (`Some(offer) ->` is a syntax
  error; `offer_is_a_keyword.march`). Swift's `Step.state` is `Step.run` here.
- **`show` as a value (not called) type-checks, then breaks both targets**:
  natively LLVM's "use of undefined value '@show'", on JS "ReferenceError:
  show is not defined" at run time. Write `fn x -> show(x)`.
  (`show_as_value/`)
- No hex literals, and no scientific Float literals. `-0.5` is fine.
- `f(x).field` is a syntax error. Bind first: `let t = f(x)`.
- `Mod.Sub.Ctor` is not a pattern. Types and constructors are visible everywhere
  without an import, and `import` only matters for functions: importing a module
  for its types alone is an `unused_import` warning.
- A name is a value, not a function, when it names a zero-argument fn: write
  `fn -> f()` to pass one. Constructors are not functions: `fn n -> Points(n)`.
- Constructors can clash with the stdlib (`Failed`, `Bar`): the compiler says
  `ambiguous_constructor`. Rename yours.
- `Json`'s constructors (`Str`, `Array`, `Object`, `Number`, `Null`, `Bool`) clash
  with `Msgpack` and `IOList`: write them `Json.Str` and so on, in patterns too.
- `then` is a keyword: a function called `then` is a parse error at its name.
  So are `affine` (a function), `len` and `by` (pattern variables).
- The stdlib owns the type `Stage` (`flow.march`) and the constructor `Trace`
  (`Method`): a type of yours called `Stage` is a different type with the same
  name, reported as a mismatch between two `Stage`s.
- A tuple on the line after a record literal is read as a call of the record:
  `{ a: 1 }` then `(x, y)` on the next line is `not_a_function`. Bind the record
  and return the tuple from a function (`Skee.Scene.pair`).
- **`Json.parse` overflows the stack on deep nesting.** A few thousand `[` crash
  it (SIGBUS natively, `RangeError` on JS). Untrusted text goes through
  `Skee.Save.parse`, which counts depth first. (`json_deep_nesting.march`)
- **`Json.to_string` writes most control characters raw.** Its `escape_of`
  escapes only `\" \\ \n \r \t \b \f`; U+0000-U+0007, U+000B and
  U+000E-U+001F come out as raw bytes, which RFC 8259, Node's JSON.parse and
  JSONSerialization all refuse. Text that leaves the device goes through
  `Skee.Host.request_body`, which escapes them as `\u00XX`.
  (`json_to_string_controls.march`)
- **`Json.parse` overflows a native stack well before Swift's limit.** Objects
  350-400 deep crash it natively (SIGBUS); node manages 1024. Swift's
  JSONDecoder reads 512 levels and refuses the 513th. `Skee.Save.parse` checks
  every level past 16 in its own tail-recursive pass and gives Json.parse an
  empty container of the same kind there, which no save decoder looks into.
  (`json_depth_probe/probe.march`)
- **Swift's JSONDecoder is looser than `Json.parse`** (golden-meta rows
  `trailingComma*`, `leaf*`, `badKey*`, `foulJunk`). It reads trailing commas;
  a string or number in a field no decoder reads is only scanned, not checked
  (`1.`, `01`, `--1`, `"\x"`, `"\uZZZZ"` all load), while `tru` is refused;
  and an enum case object counts only the keys that name a case
  (`{"foul":{},"junk":1}` is `.foul`). `Skee.Save.parse` bridges all three:
  it drops trailing commas, and replaces a string, number or key that
  Json.parse cannot read with a marker that `string_of` and `object_of`
  refuse, so it fails only where a decoder reads it, as in Swift.
- **Json.parse is looser than Swift's JSONDecoder in four places**
  (golden-meta rows `v*`, `raw*`, `bom*`, `dup*`, `*Tiny*`, from the meta
  verifier's probe). Swift refuses a raw byte below 0x20 in any string or key
  it decodes (an unread value, or a key of an object nothing opens, is only
  scanned); `Skee.Save.parse` marks such text unreadable. Swift refuses a
  number that rounds to zero from non-zero digits (`1e-400`, `2.4e-324`) as a
  Double but reads it as 0 for an Int or UInt64; `parse` marks it, `float_of`
  refuses the mark and `int_of` reads it as 0. Swift skips one leading UTF-8
  byte order mark; `parse` drops it. A repeated key keeps its first value,
  and an enum case key repeated counts once (`{"foul":{},"foul":{}}` is
  `.foul`); `lookup` is first-wins and `action_of` drops repeats before it
  counts.
- **Ints past 2^53-1 in a save are refused, not misread.** Swift reads any
  Int64 (`"balance":9007199254740993`). Json.parse holds a number as a double
  and the JS target holds Int as one, so every Int field (balance, lifetime,
  meters, comps, gamesSinceHost, hostVisits, extraTickets, the seed as a
  number) gives `SaveOutOfRange` there. The meta case "deviations from
  Swift's decoder stay as documented" (golden rows `wide`) pins it.
- **Swift writes a `[Enum: Int]` in a different order every run.** Dictionary
  order is seeded per process, so `JSONEncoder` writes the progressive meters
  in any of 24 orders even with `.sortedKeys`. `golden-meta` re-runs itself
  with `SWIFT_DETERMINISTIC_HASHING=1` so its output is stable, and the meta
  suite compares the meter pairs as a set. March writes them in tier order.
- Swift's JSONEncoder writes a dictionary whose key is a String-backed enum
  (`[Room: Comp]`, `[JackpotTier: Int]`) as one array, key then value, not as an
  object. `Skee.Save.pairs_of` reads that shape.
- An extern's callback type is written `-> ()` in `shell/glue.march`. With
  `-> Unit` the shell's first draft failed with `expected Unit but got ()` at
  its lambdas; a minimal program does not reproduce it, so there is no repro.
- **Extern declarations are private to their module.** `Glue.now()` is
  `Unknown module Glue` unless Glue defines a public `fn now()` wrapping the
  extern, as the stdlib does.
- `doc` goes before a function only. Comment a type with `--`.
- `else if` nests: each one adds an `end`.
- Float operators are `+. -. *. /.`. `/.` by zero panics natively, where Swift and
  JS give inf or NaN. `%` and `/` by zero on Int give NaN on JS.
- `float_round`, `float_floor` and friends return Int. `Math.round` is
  half-away-from-zero, like Swift's `.rounded()`.
- `float_to_string` is `%.12g`: never use it to judge parity.
- `string_to_float("inf")` is `None` on JS, `Some` elsewhere. `string_to_int` refuses
  what a double cannot hold. `process_exit` has no JS implementation: an uncaught
  panic is how a JS program exits non-zero.
- `x != x` is a working NaN test on JS and native. `float_is_nan` has no JS
  implementation. `Math.floor` and friends go through Int, so huge values differ
  by target.
- Non-tail recursion past about 5,000 frames overflows on JS.

## Modelling notes

- A `UInt64` seed is `Skee.U64.U64`: `make(hi, lo)` or `of_hex`, never a single Int.
- `[Hole: T]` became `PerHole(T)`, or `PerReel(T)` where the gutter has no entry.
  `Skee.HoleMap.reel_holes()` is `BoardSetup.reelHoles`, and spins draw in that order.
- `events` and `eventTimes` became one `List(TimedEvent)`.
- Fixed arrays became `Three(a)`, `Pockets` and `RingWalls`.
- Chips, Points, Tickets and Winnings are distinct: Swift's Ints cannot be added
  across units here. Arithmetic is in `Skee.Units`.
- `Launch` has no smart constructor in the type: build it only through
  `Skee.Physics`, which does the clamping.
